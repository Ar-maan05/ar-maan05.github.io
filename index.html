mcp-persist

Durable persistence for MCP servers · PyPI · v2.2.0 · MIT

The problem. The MCP Python SDK ships with an in-memory event store. It works until the first deploy. Restart the process and every client's Last-Event-ID points at history that no longer exists, so resumable SSE streams quietly stop being resumable. Add a second worker and it gets worse: each worker holds its own private history.

The design. mcp-persist replaces that single point of loss with swappable, durable EventStore backends. Redis covers production fleets. SQLite covers single-node deployments. PostgreSQL slots into stacks that already run it. The Redis layout is built for replay. An INCR counter issues monotonic event IDs and the events themselves live in HASHes. A per-stream ZSET supports ranged reads so a reconnecting client can resume from any point. TTLs bound storage. A key_prefix namespace makes one Redis safe for many tenants.

Adoption. Shipped at v1.0.0 and versioned steadily forward through real usage: 21,000+ downloads on PyPI and confirmed production deployments. The test suite runs 300+ async tests against fakeredis and real backends, with CI across Python 3.10 through 3.13.

Positioning. mcp-persist plugs into the official SDK's EventStore interface, so it tracks upstream releases and existing servers adopt it unchanged. Where a server can't be modified at all, the PersistenceProxy adds durability from the outside.

from mcp_persist import with_persistence

mcp = FastMCP("my-server")
app = with_persistence(mcp, backend="redis", url="redis://localhost:6379")

Full adoption is two lines. For servers you can't modify, including servers that aren't written in Python, a standalone PersistenceProxy sits in front as an ASGI layer. It tracks the full SSE state machine and replays cold or hot history to any client that reconnects.

agentfence

Learned least-privilege sandboxing for AI coding agents · Rust · Landlock · v0.1.0

Coding agents run with your full user account. A prompt injection in a README, an issue or a web page can make one read ~/.ssh, append to ~/.bashrc or drop a git hook. Least privilege is the answer, but nobody wants to hand-write a profile for every project and every agent.

agentfence derives the profile from what the agent actually did. Run Claude Code, aider or any command under agentfence learn a few times, and synth turns the traces into the smallest Landlock policy that covers them. It never grants credentials or persistence paths, even if the agent touched them while learning. run then enforces it with no root. Across 21 real agent workflows it blocked 252 of 252 attack attempts and cut the writable surface 68 to 457 times.

Learn
Records every file open, exec, directory change and network connect through strace, normalized to JSONL.
Synthesize
A weighted set-cover solver picks the fewest, narrowest grants that cover the traces, with ceilings per path role and machine-generated temp names collapsed.
Never grant secrets
SSH and cloud keys, credential stores and keyrings are dropped before the solver ever sees them, and git hooks and config stay read-only.
Enforce unprivileged
Landlock applies the profile to the agent with no root and nothing loaded system-wide, and every denial is logged.
Report
Shows what the profile blocked, grouped by kind of path, and diffs a new run against the profile.

Advisories.

Vulnerabilities I found and reported privately, published once the fixes shipped. Debug replays each one, from the bug to the fix.

  1. liske/needrestart2026-11-17High · local root

    CVE-2026-124757: local root via a forged session cgroup and the notify-send hook

    needrestart matched cgroup paths unanchored, so a user could pass their process off as part of root's session. The notify hook then put that process's self-chosen name into a shell string run as root. I wrote the three-patch fix and coordinated disclosure with Debian, Ubuntu and linux-distros.

  2. lightpanda-io/browser2026-11-04High · CVSS 7.5

    Heap buffer overflow in Frame.buf via long element and tag names

    Element and SVG tag names were lowercased into a fixed 1,024-byte buffer that release builds never bounds-checked, so one page with a long tag name overwrote the pointers after it and crashed the browser, every CDP session included. Fixed in 1.0.2.

RunixOS.

A capability-based microkernel. CS3013 Operating Systems independent study, advised by Prof. Craig Wills

RunixOS started as a from-scratch microkernel and is now my formal CS3013 Operating Systems independent study at WPI, advised by Prof. Craig Wills. It re-derives classic process, thread, and synchronization coursework on a kernel with no shared memory and no ambient authority, where every right is an explicit capability.

It's a capability-based, IPC-first microkernel written in Rust for x86_64, booting via UEFI on QEMU. The kernel implements capabilities with attenuation and revocation, a preemptible scheduler, synchronous and asynchronous IPC, and a capability-gated filesystem, all backing an interactive console with tracing and profiling tools. A companion research paper examines what preemption does to capability atomicity, tracing a real TOCTOU vulnerability from discovery through a working fix.
