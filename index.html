mcp-persist

Durable persistence for MCP servers · PyPI · v2.2.0 · MIT

The problem. The MCP Python SDK keeps resumable SSE history in memory. Restart the server or add a second worker, and reconnecting clients lose events.

The design. mcp-persist swaps in durable EventStore backends: Redis, SQLite or Postgres. Event IDs are monotonic and history supports ranged reads, so a client resumes exactly from its Last-Event-ID.

Adoption. 22,000+ downloads on PyPI and running in production, with 300+ async tests and CI across Python 3.10 to 3.13.

from mcp_persist import with_persistence

mcp = FastMCP("my-server")
app = with_persistence(mcp, backend="redis", url="redis://localhost:6379")

Two lines to adopt. For servers you can't modify, a standalone ASGI proxy adds the same replay from the outside.

Advisories

Vulnerabilities I reported privately, published once fixed.

  1. lxc/incus2026-11-27Critical · CVSS 9.9

    Restricted projects can reach host files and host root through disk devices and VM disks

    Device paths with .., guessed VM disk formats, QCOW2 backing files and a self-mapping raw.idmap let a user confined to a restricted project, incus-user included, reach host files and root. Credit shared with mmulqueen. Fixed in 7.7.0.

  2. lxc/incus2026-11-27Medium · CVSS 6.5

    Bucket GET and list disclose default-project S3 keys to projects inheriting them

    The key check ran against the requested project, not the one holding the bucket, so clients of a project inheriting default’s buckets got their S3 credentials. An incomplete fix of GHSA-pf5w-m8m6-5265. Fixed in 7.7.0.

  3. liske/needrestart2026-11-17High · CVSS 7.8

    CVE-2026-124757: local root via a forged session cgroup and the notify-send hook

    A forged session cgroup let a user get a shell string run as root through the notify hook. I wrote the three patches (cgroup matching, process names, notify hook) and coordinated disclosure.

  4. lightpanda-io/browser2026-11-04High · CVSS 7.5

    Heap buffer overflow in Frame.buf via long element and tag names

    Long tag names overflowed a fixed buffer and crashed the browser, every CDP session included. Fixed in 1.0.2.
